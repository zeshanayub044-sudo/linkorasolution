# Employee screen recording architecture

Implemented in the existing Employee Portal and Attendance Admin; no new login or parallel attendance system. Supabase remains attendance authority and the current Sheet/matrix delivery queues remain reporting mirrors.

## Deployment and activation

The additive migration creates private metadata, the private `employee-screen-recordings` Storage bucket, a scoped retention worker, and guarded existing Clock In routes. Deploy `workforce-recordings` before publishing the new pages. Existing migrations and history are preserved. Recording ships disabled (`enabled=false`, budget zero), because the account plan, paid capacity and employee monitoring policy must be approved first. An active Co-CEO can configure these under Screen Recordings → Monitoring policy and capacity. Enabling requires a positive approved budget and policy-ready acknowledgement. Once enabled, recorded Clock In is mandatory for all portal profiles allowed to clock in, including Co-CEOs who use employee attendance.

Defaults: 60-second independent video files, target 10 FPS / 500,000 bits/sec, ideal 1280×720 and maximum 1920×1080 constraints where supported, video only, 8 MiB per object, 24 MiB queued blobs, six queued files. Early rotation at 6 MB avoids holding a large file. Browser constraints and bitrate are targets, not guaranteed limits on source resolution or encoded rate. Oversized chunks interrupt recording instead of leaking memory. Sixty-second segments reduce crash loss and usually stay under the standard-upload 6 MB recommendation; 2–5-minute files at the same rate would need a different upload strategy or higher loss exposure. Each stop/restart includes a fresh container header; MediaRecorder timeslices alone are not treated as independent files.

## Employee flow

1. Supabase Auth login restores identity only; it does not start capture or new attendance.
2. The active profile fetches the versioned server monitoring notice. Employee explicitly acknowledges it before Clock In/Resume.
3. The click requests native `getDisplayMedia` before any network await. Audio is false. Cancel/deny produces no new attendance. Known tab/window sources are rejected and stopped. A browser that omits `displaySurface` receives an explicit warning; management must check that the intended entire monitor was selected.
4. MediaRecorder support and constructor are checked before starting attendance. The server validates current identity, profile, Auth session, consent version and claimed surface. Existing attendance start plus one logical recording row commit atomically.
5. The existing Presence adopts the returned session and scoped close capability. The actual encoder starts, then server activation succeeds. Existing WebRTC uses the same chosen video track; no second permission prompt or audio track is introduced.
6. Each independent segment is reserved by sequence, uploaded immutably using employee JWT, then verified by server Storage metadata before commit. Reserves retry the same path and byte count. A lost commit is reconciled server-side. Only verified files contribute to duration/size/count.
7. Clock Out stops the encoder, flushes its final event, stops capture immediately, attempts final upload for a bounded 15 seconds, then stops presence and closes attendance. All verified, ordered files make the recording provisional (`finalizing`); only successful normal attendance Clock Out marks it `completed`. A failed Clock Out stops heartbeat and uses the existing server close policy. Account logout performs this flow first and clears Auth afterward.

Native Stop Sharing interrupts recording; employee must explicitly Resume (new native permission) or Clock Out. Resume uses the same logical attendance recording, increments owner generation and preserves earlier files/retention. Incidents remain visible; a resumed or previously failed session is conservatively incomplete, even if retries recover every file. Another live tab cannot own the same recording. Old generations cannot upload against the new generation.

## Failure and concurrency

The 5-second attendance heartbeat and approximately 15-second disconnect close remain unchanged. Recording has a separate 5-second pulse and 20-second owner expiry, so another portal tab cannot falsely keep capture active. Hidden tabs do not intentionally close attendance; browser throttling/OS suspension can still expire server leases. Pagehide stops tracks and discards only unuploaded local tail; delivery on exit is not assumed. Server time determines record start, access expiry and closure; browser segment timing is bounded and represents capture metadata rather than authoritative attendance time.

Upload failures use capped exponential retry and a bounded queue; five failed attempts, authorization loss, codec failure or queue exhaustion stop recording. No persistence of screen video to localStorage/IndexedDB; a crash can lose the current 60-second file plus queued/in-flight files. Uploaded files remain reviewable; expected/missing counts and incidents are not hidden. At worst the 24 MiB queue plus current 8 MiB file and short-lived encoder/network buffers exist, rather than an 8-hour Blob.

## Server model and administration

`admin_private.screen_recording_settings`, `screen_recordings`, `screen_recording_segments` and `screen_recording_events` have RLS, no employee/anon table grants, and service-only RPC access. Employee profiles and attendance IDs use existing UUIDs and restrictive FKs. Attendance status updates trigger recording closure without deleting historical attendance. Dates/filter boundaries use company timezone (currently Asia/Karachi); bucket paths use UTC date and employee/attendance/recording UUIDs. Sequence and path uniqueness prevent overwrite/duplicate logical files.

Screen Recordings offers server-side employee/name/email/ID/date/status filters, Today/Yesterday/7/30/month/previous-month/90-day presets, 25-row pagination, metrics, capacity warnings and per-employee history. Initial attendance admin load fetches current recording badges, not every retained recording or any video. History video is loaded only after fresh Co-CEO authorization. The viewer has play/pause, seek across verified chronological segments, speed and fullscreen, plus clear segment/missing/event details. Rotation can have a small gap; playback progresses automatically rather than promising seamless stitching. Durations sum verified segments and exclude interruption gaps. The existing live WebRTC viewer remains separate and works during capture.

- `node scripts/validate.mjs`: includes seven recorder unit tests and existing attendance/browser/Sheet/matrix checks.
- `npx --yes deno@2.5.6 check supabase/functions/workforce-recordings/index.ts`
- `npx --yes deno@2.5.6 test tests/workforce-handler.test.ts tests/screen-recording-handler.test.ts`: auth, server identity, private URL signing, close capability, bounds and Storage-delete ordering.
- `tests/screen-recording-integration.sql`: transaction/rollback only against the current schema, using existing Auth UUIDs without passwords. Tests legacy-route guards, consent/source, service-role permissions, direct RLS, retries, manifests, completion, owner disconnect, crash reconciliation and retention cutoff/verification. Never leave synthetic Storage metadata outside the transaction.
- `tests/screen-recording-portal-ui.mjs` and `tests/screen-recording-admin-ui.mjs`: optional Playwright full-page Employee flow and branded recording-history/viewer desktop/mobile checks using mocked backend identities and synthetic media.
- `tests/screen-recording-encoder.mjs`: optional installed Playwright/Edge via `PLAYWRIGHT_MODULE` and `EDGE_EXECUTABLE`. Actual MediaRecorder with a synthetic 1280×720 screen, 480 accelerated rotations, private-upload mocks, decoding every file, seeking, no audio and bounded queue. This is not a real eight-hour wall-clock endurance test, real object upload or native capture permission test.

Before enabling production, an employee and a Co-CEO must test: native Entire Screen/cancel/window selection, readable work text, live viewer plus real private upload/playback, Clock Out/logout, native Stop Sharing and resume, two tabs, brief outage and >15-second outage, browser force-close after several real uploads, and physical Storage deletion/expiry using disposable consented test content. Verify admin mobile playback/layout too. No passwords should be supplied in chat. Keep mandatory recording disabled until budget and these operator acceptance results are confirmed.
