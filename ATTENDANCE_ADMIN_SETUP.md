# Attendance Admin setup

The official employee route is `tennis-portal.html`; the dedicated Co-CEO route is `attendance-admin.html`. The older `attendance.html` URL redirects to the employee portal because its Google-only attendance path could not provide an authoritative Supabase record. `attendance.js` and `activity-config.js` are retained as historical integration files but are no longer loaded by that route. The existing Blog and Careers systems are unchanged.

## Architecture and access

Supabase Auth identifies the person. `employee_profiles.id` must match the Auth UUID. An active profile with role `Co-CEO` is the sole administrator rule; the admin page checks it before requesting data, and every reporting/mutation RPC checks `public.is_admin()` again. `admin-users` checks the bearer token, active Auth user, and active Co-CEO profile before its service-role operations. `manage-employee` checks the bearer token with Supabase Auth and the active profile; only Co-CEOs can request its report or Sheets retry action. The service-role key and Sheets secret remain Edge Function environment secrets, never browser assets.

The employee lifecycle is Auth login → `manage-employee` → `portal_employee_start_session` → `employee_activity_sessions`; sign-out uses `portal_employee_end_session`. The service-role RPCs lock the profile and keep at most one new current-day open session. On the next login, older open sessions are marked `Needs Review` and system-audited without inventing logout times. An old browser-tab session ID falls back to the employee's latest open session at sign-out. If only an old session exists, sign-out flags it for review instead of assigning today's time as a historical logout. Browser session storage contains only the session UUID. Supabase timestamps are UTC; daily and monthly boundaries, late arrival, and display use `company_settings.timezone` (currently `Asia/Karachi`).

The migration adds `employee_active_periods` to bound absence calculations to each employee's active intervals. A day is absent only when it was scheduled, the account was active at the scheduled start, the cutoff has passed, and no session exists. No fake absence row is stored. Completed duration is `logout_at - login_at` on the server. Open duration is display-only. Monthly reports aggregate the bounded daily RPC; history is filtered and paginated by Postgres, including status.

## Admin modules

The dashboard shows workforce counts and a seven-day trend. Live Attendance uses a separate Co-CEO RPC for the latest valid current-day open session, so elapsed time stays correct after same-day re-entry; it distinguishes old sessions needing review. Employees reuses the existing `admin-users` Edge Function for Auth user creation, editing, activation/deactivation, and manual status changes; deactivation preserves sessions and audit history. The detail panel includes today's activity, monthly figures, daily breakdown, and recent sessions. Today, Monthly, History, Reports, Issues, Audit, and Settings use `portal_attendance_*` RPCs. CSV exports escape spreadsheet formula prefixes. Large history is loaded only when requested in bounded pages.

Manual additions and corrections require a reason and create `portal_admin_audit_log` entries with actor, target, before/after state, and time. The Settings RPC audits schedule changes. Manual status changes through `admin-users` require a reason and reject an old or multiple-open sign-out; deactivation flags old/duplicate rows for review and closes only a valid current session. Existing malformed/duplicate sessions are displayed under Attendance Issues for explicit review.

## Secondary Google Sheets mirror

The recent user or admin status trigger inserts rows into `attendance_sheet_sync_queue` in the same database transaction as the Supabase session change. `manage-employee` returns the successful attendance response immediately and schedules a background webhook attempt; `admin-users` requests the same queue worker after an admin status change or deactivation. A failed webhook leaves the authoritative session intact, records the error and a retry time, and can be retried from Admin → Settings → **Retry Sheet sync**. Keep `GOOGLE_APPS_SCRIPT_URL` and `GOOGLE_SHEETS_WEBHOOK_SECRET` in Edge Function secrets. The queue is service-role-only; manual historical corrections do not automatically rewrite the sheet. The mirror is at-least-once, so consumers should deduplicate by session ID and action. If the Edge Runtime background task cannot run, the pending queue persists for an admin retry.

## Deployment

1. Deploy the versioned files from this repository, including `attendance-admin.html`, `attendance-admin.css`, `attendance-admin.js`, the updated Tennis Portal files, and the `attendance.html` redirect. Ensure the existing ignored `portal-config.js` supplies the public Supabase URL and anon key in production; do not commit service credentials.
2. Apply only the new migrations in timestamp order: `20261007010635_attendance_admin.sql`, `20261007010825_attendance_sync_and_issues.sql`, `20261007011741_attendance_audit_actions.sql`, `20261007012051_attendance_history_filter.sql`, `20261007012543_attendance_settings_grants.sql`, `20261007013104_admin_attendance_sheet_queue.sql`, `20261007013537_attendance_live.sql`, `20261007014254_safe_admin_signout.sql`, and `20261007014359_safe_employee_signout.sql`. These are already applied to project `nbvylffxmjmovyfhbytu`; do not reset production or replay them manually.
3. Deploy `supabase/functions/manage-employee/index.ts` with the existing custom Auth verification configuration (`verify_jwt=false`; the function validates the bearer using `auth.getUser`). Deploy `supabase/functions/admin-users/index.ts` with `verify_jwt=true`. Production currently has versions 22 and 5 respectively. The latter uses the project's standard `SUPABASE_ANON_KEY` to invoke the queue worker after admin changes.
4. Open `attendance-admin.html` with each active Co-CEO account. Confirm unauthorized identities see the access-denied gate. Use employee portal sign-in/sign-out to verify the new queue and live view. Review pending anomalies before correcting any historical time.

## Verification performed

Production SQL tests used rollback-only transactions for employee start/end (including repeated sign-in and stale-tab sign-out), manual add/correction, employee edit/deactivation, settings change, and audit creation. A real CEO001 portal sign-in through the deployed service created a session, flagged six stale records, and queued a mirror item. Both Co-CEO identities reached reporting RPCs; an employee identity was denied. Monthly aggregation and pre-activation absence behavior were queried. JavaScript and Edge TypeScript syntax checks and `git diff --check` passed; the local unauthenticated admin page showed the login gate. End-to-end Co-CEO browser admin login, Auth account creation, and successful webhook delivery still require an authorized interactive session and were not claimed as tested. See `ATTENDANCE_ADMIN_SECURITY_AUDIT.md` and `ATTENDANCE_DATA_HEALTH.md`.
